Review gate · no-mistakes, two axes

Runs per project, not per UI session — several projects can be under review at once. The gate must show which project and which diff before it shows a verdict.

Axis 1 — spec conformance

  • Does the diff do what the task asked, and only that?
  • Are the original tests still asserting the original contract?
  • Deleted assertions are findings, not fixes.

Axis 2 — quality & risk

  • Regression surface: every caller of a changed function.
  • Additive vs destructive: prefer added fields over replaced ones.
  • CI parity: the same gate the repo runs.
